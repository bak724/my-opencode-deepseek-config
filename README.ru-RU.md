# My OpenCode × DeepSeek Config

[简体中文](README.md) | [繁體中文](README.zh-TW.md) | [English](README.en-US.md) | **Русский** | [Français](README.fr-FR.md) | [Deutsch](README.de-DE.md) | [Español](README.es-ES.md) | [Português](README.pt-BR.md) | [日本語](README.ja-JP.md) | [한국어](README.ko-KR.md)

**Оптимальная конфигурация OpenCode × DeepSeek** — конфигурация, максимально раскрывающая возможности двух моделей DeepSeek V4 (Pro + Flash) в мультиагентном фреймворке OpenCode. Ключевой принцип: **эффективность токенов прежде всего — лучший результат разработки при минимальной стоимости контекста**.

## Обзор текущей конфигурации

- Основной агент по умолчанию: `orchestrator`
- Основная модель: `deepseek/deepseek-v4-pro`, лёгкая модель: `deepseek/deepseek-v4-flash`
- Вложенность агентов: `subagent_depth: 3` (поддерживается 3 уровня вложенности)
- Изоляция моделей: `enabled_providers: ["deepseek"]` — единственная привязка
- Общий доступ к сессиям: выключен (`share: "disabled"`); снимки: включены (`snapshot: true`)
- Базовый уровень разрешений: по умолчанию разрешено, разрушительные bash-команды — `ask`; чувствительные файлы вида `.env` — `deny`; внешние каталоги — `ask`; bash-белый список для read-only агентов (по умолчанию deny всё + разрешены только read-only подкоманды)
- Сжатие контекста: встроенная компакция (opencode.jsonc) управляет автоматическим запуском + prune урезает устаревшие выводы инструментов, DCP (dcp.jsonc) отвечает за активную дедупликацию + пороги сжатия — они дополняют друг друга
- Глобальные правила: `AGENTS.md` (ключевые принципы, контракт отклонения задач, самопроверка, антипаттерны и др.; дисциплина контекста/токенов перенесена в `orchestrator`)
- Навыки: **23** навыка `SKILL.md` в каталоге `skills/`, загружаются по запросу через нативный инструмент `skill`
- Плагины: `superpowers` (v6.3.0, процессные навыки), `@tarquinen/opencode-dcp` (интеллектуальная обрезка контекста)

## Конфигурация моделей DeepSeek

### Предварительные условия

- OpenCode ≥ v1.18.x (провайдер DeepSeek встроен)
- API-ключ DeepSeek: получите на [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys)

### Способ 1: интерактивная настройка в TUI (рекомендуется)

```bash
opencode
# В TUI введите: /connect → выберите DeepSeek → вставьте API-ключ
# Затем: /models → выберите deepseek-v4-pro
```

API-ключ автоматически сохранится в `~/.local/share/opencode/auth.json`.

### Способ 2: переменная окружения

Windows PowerShell:
```powershell
$env:DEEPSEEK_API_KEY="sk-your-key-here"
opencode
```

Постоянная настройка: добавьте `DEEPSEEK_API_KEY` в системные переменные окружения.

### Справочная конфигурация провайдера

```jsonc
{
  "model": "deepseek/deepseek-v4-pro",
  "small_model": "deepseek/deepseek-v4-flash",
  "enabled_providers": ["deepseek"]
}
```

Если для модели Pro нужно включить thinking/reasoning, добавьте в `provider`:

```jsonc
"provider": {
  "deepseek": {
    "models": {
      "deepseek-v4-pro": {
        "options": {
          "thinking": { "type": "enabled" }
        }
      }
    }
  }
}
```

> **Правила именования ID моделей**: `provider_id/model_id`, то есть `deepseek/deepseek-v4-pro` и `deepseek/deepseek-v4-flash`.

## Установка и развёртывание

### Способ 1: клонирование + переменная окружения (рекомендуется, кроссплатформенно)

```bash
git clone https://github.com/znlgis/my-opencode-deepseek-config.git
```

Затем укажите `OPENCODE_CONFIG_DIR` на подкаталог `opencode/` внутри репозитория — и можно пользоваться.

**Windows (PowerShell)** — навсегда:

```powershell
[Environment]::SetEnvironmentVariable("OPENCODE_CONFIG_DIR", "D:\path\to\my-opencode-deepseek-config\opencode", "User")
```

**Windows (PowerShell)** — временно (только текущая сессия):

```powershell
$env:OPENCODE_CONFIG_DIR = "D:\path\to\my-opencode-deepseek-config\opencode"
opencode
```

**Linux / macOS** — добавьте в `~/.bashrc` или `~/.zshrc`:

```bash
export OPENCODE_CONFIG_DIR="$HOME/path/to/my-opencode-deepseek-config/opencode"
```

### Способ 2: символическая ссылка на глобальный каталог конфигурации

**Windows (PowerShell, требуются права администратора):**

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.config"
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.config\opencode" -Target "D:\path\to\my-opencode-deepseek-config\opencode"
```

**Linux / macOS:**

```bash
ln -s /path/to/my-opencode-deepseek-config/opencode ~/.config/opencode
```

> **Примечание о совместимости**: `~/.config/opencode` — стандартный глобальный путь конфигурации OpenCode. Подкаталог `opencode/` этого репозитория содержит `agents/`, `skills/`, `AGENTS.md` и другие файлы; раскладка полностью следует соглашениям OpenCode, и после указания через переменную окружения или символическую ссылку всё распознаётся автоматически.

### Проверка установки

Запустите OpenCode и убедитесь:
1. `/models` → текущая модель — `deepseek/deepseek-v4-pro`
2. В списке агентов видны все 10 агентов: `orchestrator`, `planner`, `deep-worker` и др.
3. Введите любой запрос — Orchestrator автоматически определит намерение и направит по маршруту

## Разделение моделей

В этом репозитории строго используется разделение труда между двумя моделями DeepSeek V4, другие модели не подключаются:

| Модель | Назначение |
| --- | --- |
| `deepseek/deepseek-v4-pro` | планирование, архитектура, анализ первопричин, код-ревью, тяжёлая реализация, диспетчеризация |
| `deepseek/deepseek-v4-flash` | быстрая разведка, внешний поиск, лёгкие задачи, простые правки |

### Стратегия маршрутизации

- **Flash прежде всего**: чётко определённые задачи — поиск, подбор, простые правки — сначала идут flash-агенту
- **Pro сосредоточен на рассуждениях**: планирование, анализ, ревью, сложная реализация — только pro
- **Автоматическое повышение**: если flash-агент не справляется, задача автоматически повышается до pro (с полным контекстом)

## Структура агентов

### Primary Agent

| Агент | Модель | Роль |
| --- | --- | --- |
| `orchestrator` | v4-pro | точка входа по умолчанию: контроль намерений (Intent Gate) + маршрутизация с учётом модели + цепочка отката |

### Subagents

| Агент | Модель | Права | Роль |
| --- | --- | --- | --- |
| `planner` | v4-pro | чтение/запись | планирование, архитектура, декомпозиция задач |
| `deep-worker` | v4-pro | чтение/запись | тяжёлая реализация, многофайловые правки, сложная отладка |
| `oracle` | v4-pro | **только чтение** | анализ первопричин, глубокое понимание кода |
| `reviewer` | v4-pro | **только чтение** | двухосевое код-ревью (стандарты + спецификации) + калибровка серьёзности |
| `ui-builder` | v4-pro | чтение/запись | задачи фронтенда и UI |
| `consultant` | v4-pro | чтение/запись | обсуждение решений, советы по лучшим практикам |
| `explore` | v4-flash | **только чтение** | поиск по кодовой базе, параллельная разведка |
| `librarian` | v4-flash | **только чтение** | поиск по документации, веб-поиск |
| `light-orchestrator` | v4-flash | чтение/запись | лёгкие задачи, правка одного файла |

> `deep-worker` и `light-orchestrator` следуют принципу «никаких исследований, никакого делегирования» — они исполняют, а не разведывают; контекст предоставляет orchestrator.
>
> Read-only агенты (`oracle`/`reviewer`/`explore`/`librarian`) действительно только читают: `edit: deny` + bash-белый список (по умолчанию deny всё, разрешены только read-only подкоманды `git status/diff/log/show/blame/grep`, `rg` и т.п.; `oracle`/`reviewer` дополнительно разрешены `gh pr view/diff`, `gh issue view`, `gh api` для поддержки ответов через `/review-pr`).

## Навыки (Skills)

OpenCode предоставляет навыки по запросу через нативный инструмент `skill` — агент загружает их только при необходимости, не расходуя контекст.

| Skill | Назначение |
| --- | --- |
| `code-review` | экономичное по токенам многоаспектное код-ревью: отчёт по аспектам + степеням серьёзности, совпадающие замечания с наивысшей уверенностью, самоопровержение deepreview, никогда не правит код без запроса |
| `codemap` | генерация размеченной карты структуры репозитория, быстрая ориентация, экономия токенов на разведку |
| `gh-cli` | справочник GitHub CLI v2.97+: пагинация, выбор репозитория, discussions/projects/rulesets/skills, rate limit, agentic CI gh-aw, фолбэк gh api |
| `git-master` | продвинутые операции Git: rebase, squash, fixup, bisect, reflog, археология кода, worktree |
| `git-release` | релиз с тегом: заметки о релизе, вывод SemVer, команда gh release |
| `resolving-merge-conflicts` | разрешение конфликтов слияния по hunk: восстановление исходного замысла, никогда не изобретать новое поведение, никогда не --abort |
| `handoff` | сжатие сессии в документ передачи (ссылки на пути, без копирования содержимого) |
| `opencode-config` | написание и сопровождение конфигурации OpenCode этого репозитория (agents/skills/commands/permissions) |
| `reflect` | непрерывное улучшение: выявление трений → минимальные сопровождаемые исправления |
| `remove-deadcode` | безопасный поиск и удаление мёртвого кода, проверка через toolchain/LSP перед удалением |
| `security-review` | проверка безопасности перед слиянием (инъекции/XSS/SSRF/секреты/десериализация/обход путей), только отчёт без правок |
| `shared-language` | построение глоссария доменных терминов (CONTEXT.md), значительная экономия токенов |
| `simplify` | упрощение кода с сохранением поведения (анализ oracle → применение) |
| `spec-workflow` | лёгкие изменения, управляемые спецификацией: proposal → specs → design → tasks → archive |
| `verification-planning` | планирование самого узкого пути проверки до реализации |
| `verify-with-docs` | сверка API с документацией перед написанием кода, приоритет поиска, защита от галлюцинаций |
| `grilling` | интервью для выравнивания требований: по одному вопросу за раз, предпочтение вариантов, сведение неоднозначности до начала работы |
| `tech-debt-audit` | аудит технического долга по 9 измерениям (мёртвый код/дублирование/дрейф имён/сложность/зависимости/обработка ошибок/тесты/документация/безопасность), read-only отчёт без правок |
| `wait-what` | если сообщение пользователя непонятно — сначала пересказать одним предложением и подтвердить, потом действовать |
| `writing-for-agents` | рычаги письма для документов, адресованных агентам (skill/AGENTS.md/документы-указатели) |
| `to-questionnaire` | разовая анкета вне канала (асинхронное заполнение), в отличие от живого интервью grilling |
| `research` | глубокое исследование открытой темы, результат — Markdown с цитатами, в отличие от точечной сверки verify-with-docs |
| `wizard` | пошаговый мастер для человека (bash-скрипт, проверка `bash -n`), ведёт человека по шагам, которые может выполнить только он сам |

## Дизайнерские решения и журнал итераций

Ключевые идеи заимствуют сильные стороны [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent) (контроль намерений, изоляция read-only, антипаттерны), [oh-my-opencode-slim](https://github.com/alvinunreal/oh-my-opencode-slim) (приоритет диспетчера, цепочка отката, контракт отклонения, безопасность кэша промптов, impact×confidence÷cost), [anomalyco/opencode](https://github.com/anomalyco/opencode) (схема конфигурации, система навыков), [cli/cli](https://github.com/cli/cli) (набор команд gh v2.97, rate limit, gh-aw), [OpenSpec](https://github.com/Fission-AI/OpenSpec) (delta specs, поток действий OPSX update/verify/четыре вопроса), [mattpocock/skills](https://github.com/mattpocock/skills) (дисциплина разрешения конфликтов, документы передачи), [pi](https://github.com/earendil-works/pi) (сначала ответ, потом правки; лаконичные ответы; сбор в независимых сессиях) и [deepreview](https://github.com/mechanai/deepreview) (сходимость классификации novelty, маршрутизация по эффективному размеру, Points of Agreement). Реализовано чистой конфигурацией, ноль дополнительных зависимостей.

> **Заимствование, а не копирование**: из тяжеловесных пайплайнов берутся только облегчённые концепции дизайна; избыточные функции покрываются существующими agents/skills, ничего нового не добавляется. Следуем принципу «минимализм прежде новых фич» — цель каждой итерации: чистое сокращение токенов.
>
> **Источники механизмов текущего раунда (v28)**: дисциплина кэша DeepSeek + thinking, scope-first + приоритет делегирования, атомарные TODO перенесены в AGENTS.md; добавлены 5 навыков (wait-what/writing-for-agents/to-questionnaire/research/wizard), всего 23; в gh-cli добавлены 4 пункта безопасности GHSA; в code-review встроено самоопровержение deepreview; удалён .ai/calibration.yml (правила калибровки встроены в code-review).
>
> **Оценено и не принято**: прочие процессные навыки из mattpocock/skills (code-review, tdd, implement и т. д. — пересекаются с superpowers и существующими навыками); у superpowers нет ручек конфигурации — оставлена инъекция в виде строки плагина.

### Вехи итераций

С версии v1 пройдено 28 итераций, непрерывно сверяемся с лучшими практиками вышестоящих репозиториев:

- **v1-v7 (фундамент)**: привязка двух моделей, система ролей агентов, маршрутизация с контролем намерений, глобальные правила AGENTS.md, каталог Skills, базовый уровень разрешений
- **v8-v15 (ревью+спецификации+контракт)**: двухосевая калибровка code-review, spec-workflow, выравнивание gh-cli, контракт отклонения задач, фоновая проверка
- **v16-v22 (непрерывное похудение)**: команды 29→18 (-38%), AGENTS.md 290→211 (-27%), построчная обрезка no-op, проверка схемы и удаление мёртвых ключей
- **v23-v25 (выравнивание+безопасность)**: интеграция 6 вышестоящих репозиториев, раздел безопасности с экранированием в gh-cli v2.97, уточнение procedure-driven промптов, настройка окна DCP
- **v26 (похудение этого раунда)**: prune:true и ужесточение tool_output 800/20480, переход DCP на процентные пороги 60%/30%, введение grilling вместо writing-great-skills, сокращение opencode-config 131→64, уровни серьёзности + validator в code-review, добавление gh status в gh-cli, User Override в AGENTS.md, дисциплина стоимости делегирования в orchestrator, чистое сокращение 22 строк в 7 файлах агентов
- **v27 (удаление/миграция/добавление)**: удалена мёртвая конфигурация batch_tool, бесполезный `write: deny` у read-only агентов, 3 избыточные bash-строки; раздел Context Management перенесён в отдельную подсекцию orchestrator; bash-белый список read-only агентов, в read добавлен `.env`; добавлен навык tech-debt-audit; описания 15 навыков похудели на 30-40%; в gh-cli добавлены 5 пунктов (rate limit/хост gh skill/gh-aw и др.), в code-review добавлены Points of Agreement, в spec-workflow — два вопроса update, в orchestrator — сбор независимых сессий + безопасность кэша промптов, в deep-worker — impact×confidence÷cost
- **v28 (рефакторинг дисциплины)**: дисциплина кэша + thinking, scope-first + приоритет делегирования, атомарные TODO перенесены в AGENTS.md; добавлены 5 навыков, всего 23; в gh-cli добавлены 4 пункта GHSA; в code-review встроено самоопровержение deepreview; удалён .ai/calibration.yml (правила встроены в code-review); README синхронизирован на 10 языках

## Руководство по использованию

### Режим 1: автоматическая маршрутизация Orchestrator (по умолчанию)

Опишите задачу естественным языком — Orchestrator автоматически определит намерение, выберет подходящего агента и модель для исполнения.

```text
«Помоги разобраться с ошибкой этого API входа»          → oracle анализирует первопричину → возвращает диагностический отчёт
«Оптимизируй этот цикл, производительность никуда не годится» → oracle анализирует → deep-worker внедряет оптимизацию
«Проверь, пожалуйста, этот PR»                    → reviewer проводит многоаспектное ревью → возвращает отчёт с уровнями серьёзности
«Хочу добавить функцию экспорта в модуль пользователей» → planner составляет план → deep-worker реализует
«Как использовать API use() в React 19»          → librarian ищет в документации → возвращает сигнатуру и примеры
```

### Режим 2: прямые алиасы команд

### Типичные рабочие процессы

**Разработка новой функции (управляется спецификацией):**
```text

```

**Отладка бага:**
```text

```

**Код-ревью:**
```text

```

## Философия дизайна

- **Чистая конфигурация, ноль дополнительных зависимостей** — все возможности реализованы через `opencode.jsonc` + `agents/*.md` + `skills/*/SKILL.md` + `AGENTS.md`
- **Максимальное использование двух моделей DeepSeek V4** — Pro рассуждает и принимает решения, Flash ищет и выполняет лёгкие задачи
- **Эффективность токенов прежде всего** — ссылки на пути вместо вставки файлов, навыки по запросу, многоуровневое управление сжатием
- **Плагины усиливают, но не доминируют** — superpowers даёт процессную дисциплину, DCP (dcp.jsonc) — активную дедупликацию + пороги сжатия, встроенная компакция (opencode.jsonc) — автоматический запуск + подстраховка prune
- **Разделение исполнения и разведки** — deep-worker/light-orchestrator не исследуют и не делегируют, explore/librarian не изменяют
- **Дисциплина кэша и thinking** — стабильный статический префикс для попадания в кэш промптов DeepSeek; температура 0 для задач кодирования; thinking включается только для задач рассуждений, для простых/поисковых задач выключается
- **Scope First + Delegate Always** — сначала определи масштаб (2+ шагов / несколько файлов / архитектурные изменения сначала идут в planner), затем делегируй исполнение; токены верхнего уровня тратятся только на маршрутизацию и сложные задачи
- **Атомарные TODO** — для многошаговых задач сначала упорядоченный список TODO, каждый пункт по очереди in_progress→completed; формат `path: action for scenario — verify by check`
- **Непрерывное улучшение** — reflect механизирует выявление трений, двухосевая калибровка code-review гарантирует качество
