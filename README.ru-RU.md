# My OpenCode × DeepSeek Config

[简体中文](README.md) | [繁體中文](README.zh-TW.md) | [English](README.en-US.md) | **Русский** | [Français](README.fr-FR.md) | [Deutsch](README.de-DE.md) | [Español](README.es-ES.md) | [Português](README.pt-BR.md) | [日本語](README.ja-JP.md) | [한국어](README.ko-KR.md)

**Оптимальная конфигурация OpenCode × DeepSeek** — конфигурация, раскрывающая возможности связки из двух моделей DeepSeek V4 (Pro + Flash) на максимум в мульти-агентном фреймворке OpenCode. Ключевой принцип: **эффективность токенов прежде всего — достижение наилучших результатов разработки при минимальных затратах контекста**.

## Обзор текущей конфигурации

- Основной агент по умолчанию: `orchestrator`
- Основная модель: `deepseek/deepseek-v4-pro`, лёгкая модель: `deepseek/deepseek-v4-flash`
- Глубина субагентов: `subagent_depth: 3` (поддерживает 3 уровня вложенности агентов)
- Изоляция моделей: двойная блокировка `enabled_providers: ["deepseek"]` + `disabled_providers`
- Общий доступ к сессии: отключён (`share: "disabled"`); снимки: включены (`snapshot: true`)
- Базовые разрешения: по умолчанию разрешено, деструктивные bash-команды — `ask`; чувствительные файлы (`.env`) — `deny`; внешние каталоги — `ask`; белые списки bash для агентов только-чтение (по умолчанию deny для всего + разрешены только read-only подкоманды)
- Сжатие контекста: проактивное сжатие DCP при пороге 60% + нативная auto compaction OpenCode как подстраховка при приближении к переполнению, два взаимодополняющих уровня (prune отсекает старые выводы инструментов)
- Глобальные правила: `AGENTS.md` (ключевые принципы, контракт отказа от задач, самопроверка, анти-паттерны и т.д.; дисциплина управления контекстом/токенами перенесена в `orchestrator`)
- Навыки: **18** навыков `SKILL.md` в каталоге `skills/`, загружаемых по требованию через нативный инструмент `skill`
- Плагины: `superpowers` (v6.3.0, процессные навыки), `@tarquinen/opencode-dcp` (интеллектуальная обрезка контекста)

## Конфигурация моделей DeepSeek

### Предварительные требования

- OpenCode ≥ v1.14.24 (провайдер DeepSeek встроен)
- API-ключ DeepSeek: получите на [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys)

### Способ 1: Интерактивная настройка через TUI (рекомендуется)

```bash
opencode
# В TUI введите: /connect → выберите DeepSeek → вставьте API-ключ
# Затем: /models → выберите deepseek-v4-pro
```

API-ключ будет автоматически сохранён в `~/.local/share/opencode/auth.json`.

### Способ 2: Переменные окружения

Windows PowerShell:
```powershell
$env:DEEPSEEK_API_KEY="sk-your-key-here"
opencode
```

Постоянная настройка: добавьте `DEEPSEEK_API_KEY` в системные переменные окружения.

### Справочник конфигурации провайдера

```jsonc
{
  "model": "deepseek/deepseek-v4-pro",
  "small_model": "deepseek/deepseek-v4-flash",
  "enabled_providers": ["deepseek"],
  "disabled_providers": ["openai", "anthropic", "google", "openrouter"]
}
```

Чтобы включить thinking/reasoning для модели Pro, добавьте в `provider`:

```jsonc
"provider": {
  "deepseek": {
    "models": {
      "deepseek-v4-pro": {
        "options": {
          "thinking": { "type": "enabled" }
        }
      }
    }
  }
}
```

> **Правило именования ID моделей**: `provider_id/model_id`, т.е. `deepseek/deepseek-v4-pro` и `deepseek/deepseek-v4-flash`.

## Установка и развёртывание

### Способ 1: Клонирование + переменная окружения (рекомендуется, кроссплатформенно)

```bash
git clone https://github.com/znlgis/my-opencode-deepseek-config.git
```

Затем укажите `OPENCODE_CONFIG_DIR` на подкаталог `opencode/` внутри репозитория.

**Windows (PowerShell)** —— постоянно:

```powershell
[Environment]::SetEnvironmentVariable("OPENCODE_CONFIG_DIR", "D:\path\to\my-opencode-deepseek-config\opencode", "User")
```

**Windows (PowerShell)** —— временно (только текущая сессия):

```powershell
$env:OPENCODE_CONFIG_DIR = "D:\path\to\my-opencode-deepseek-config\opencode"
opencode
```

**Linux / macOS** —— добавить в `~/.bashrc` или `~/.zshrc`:

```bash
export OPENCODE_CONFIG_DIR="$HOME/path/to/my-opencode-deepseek-config/opencode"
```

### Способ 2: Символическая ссылка на глобальный каталог конфигурации

**Windows (PowerShell, требуются права администратора):**

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.config"
New-Item -ItemType SymbolicLink -Path "$env:USERPROFILE\.config\opencode" -Target "D:\path\to\my-opencode-deepseek-config\opencode"
```

**Linux / macOS:**

```bash
ln -s /path/to/my-opencode-deepseek-config/opencode ~/.config/opencode
```

> **Примечание о совместимости**: `~/.config/opencode` — стандартный путь глобальной конфигурации OpenCode. Подкаталог `opencode/` этого репозитория содержит `agents/`, `skills/`, `AGENTS.md` и другие файлы, структура полностью соответствует соглашениям OpenCode — при указании через переменную окружения или символическую ссылку они распознаются автоматически.

### Проверка установки

Запустите OpenCode и проверьте:
1. `/models` → текущая модель `deepseek/deepseek-v4-pro`
2. В списке агентов должны отображаться 10 агентов: `orchestrator`, `planner`, `deep-worker` и др.
3. Введите любой запрос — Orchestrator автоматически проанализирует намерение и направит его нужному агенту

## Распределение моделей

Этот репозиторий строго ограничен распределением задач между двумя моделями DeepSeek V4, без привлечения других моделей:

| Модель | Назначение |
| --- | --- |
| `deepseek/deepseek-v4-pro` | Планирование, архитектура, анализ первопричин, код-ревью, сложная реализация, основная диспетчеризация |
| `deepseek/deepseek-v4-flash` | Быстрое исследование, внешний поиск, лёгкие задачи, простые правки |

### Стратегия маршрутизации

- **Flash в первую очередь**: чётко определённые задачи — поиск, просмотр, простые правки — направляются flash-агентам
- **Pro для рассуждений**: планирование, анализ, ревью, сложная реализация — только pro
- **Автоматическое повышение**: если flash-агент не справляется, задача автоматически передаётся pro (с полным контекстом)

## Структура агентов

### Основной агент

| Агент | Модель | Роль |
| --- | --- | --- |
| `orchestrator` | v4-pro | Точка входа по умолчанию: шлюз намерений (Intent Gate) + маршрутизация с учётом модели + цепочка резервирования |

### Субагенты

| Агент | Модель | Права | Роль |
| --- | --- | --- | --- |
| `planner` | v4-pro | чтение/запись | Планирование, архитектура, декомпозиция задач |
| `deep-worker` | v4-pro | чтение/запись | Сложная реализация, многофайловые изменения, сложная отладка |
| `oracle` | v4-pro | **только чтение** | Анализ первопричин, глубокое понимание кода |
| `reviewer` | v4-pro | **только чтение** | Двухосевое код-ревью (стиль + спецификация) + калибровка серьёзности |
| `ui-builder` | v4-pro | чтение/запись | Задачи, связанные с фронтендом и UI |
| `consultant` | v4-pro | чтение/запись | Обсуждение решений, рекомендации по лучшим практикам |
| `explore` | v4-flash | **только чтение** | Поиск по кодовой базе, параллельное исследование |
| `librarian` | v4-flash | **только чтение** | Поиск по документации, веб-поиск |
| `light-orchestrator` | v4-flash | чтение/запись | Лёгкие задачи, правки одного файла |

> `deep-worker` и `light-orchestrator` следуют принципу «запрет исследований, запрет делегирования» — исполнение, а не исследование; контекст предоставляется orchestrator.
>
> Агенты только-чтение (`oracle`/`reviewer`/`explore`/`librarian`) по-настоящему только-чтение: `edit: deny` + белые списки bash (по умолчанию deny для всего, разрешены только read-only подкоманды — `git status/diff/log/show/blame/grep`, `rg` и т.д.; `oracle`/`reviewer` дополнительно разрешены `gh pr view/diff`, `gh issue view`, `gh api` для поддержки публикации комментариев `/review-pr`).

## Навыки (Skills)

OpenCode предоставляет навыки по требованию через нативный инструмент `skill` — агент загружает их только при необходимости, не расходуя контекст.

| Навык | Назначение |
| --- | --- |
| `code-review` | Многомерное код-ревью с экономией токенов: отчёт с градацией по измерениям и серьёзности, точки согласия помечаются максимальной уверенностью, код никогда не правится самовольно |
| `codemap` | Генерация аннотированной карты репозитория для быстрой ориентации, экономия токенов на исследование |
| `gh-cli` | Справочник GitHub CLI v2.97+: пагинация, определение репозитория, discussions/projects/rulesets/skills, rate limit, agentic CI gh-aw, резервный gh api |
| `git-master` | Продвинутые операции Git: rebase, squash, fixup, bisect, reflog, археология кода, worktree |
| `git-release` | Релиз с тегом: примечания к релизу, определение SemVer, команда gh release |
| `resolving-merge-conflicts` | Разрешение конфликтов слияния по каждому hunk: отслеживание исходного замысла, никогда не изобретать новое поведение, никогда не --abort |
| `handoff` | Сжатие сессии в документ передачи (ссылки на пути, без копирования содержимого) |
| `opencode-config` | Создание и поддержка конфигурации OpenCode этого репозитория (agents/skills/commands/permissions) |
| `reflect` | Непрерывное улучшение: выявление проблем → минимальные поддерживаемые исправления |
| `remove-deadcode` | Безопасный поиск и удаление мёртвого кода, проверка инструментами/LSP перед удалением |
| `security-review` | Аудит безопасности перед слиянием (инъекции/XSS/SSRF/секреты/десериализация/обход пути), только отчёт без правок |
| `shared-language` | Построение глоссария предметной области (CONTEXT.md), значительная экономия токенов |

| `verification-planning` | Планирование минимального пути верификации перед реализацией |

| `grilling` | Интервью по согласованию требований: один вопрос за раз, приоритет вариантов выбора, действовать после устранения неоднозначности |
| `tech-debt-audit` | Аудит технического долга по 9 измерениям (мёртвый код/дублирование/дрейф именования/сложность/зависимости/обработка ошибок/тесты/документация/безопасность), только отчёт без правок |

## Проектные решения и история итераций

Ключевые идеи заимствованы у [oh-my-openagent](https://github.com/code-yeongyu/oh-my-openagent) (шлюз намерений, изоляция только-чтение, анти-паттерны), [oh-my-opencode-slim](https://github.com/alvinunreal/oh-my-opencode-slim) (приоритет диспетчера, цепочка резервирования, контракт отказа, безопасность кэша промптов, impact×confidence÷cost), [anomalyco/opencode](https://github.com/anomalyco/opencode) (схема конфигурации, система навыков), [cli/cli](https://github.com/cli/cli) (набор команд gh v2.97, rate limit, gh-aw), [OpenSpec](https://github.com/Fission-AI/OpenSpec) (дельта-спецификации, поток действий OPSX update/verify/четыре вопроса), [mattpocock/skills](https://github.com/mattpocock/skills) (дисциплина разрешения конфликтов, документы передачи), [pi](https://github.com/earendil-works/pi) (сначала ответ, потом правка; лаконичные ответы; сбор контекста в отдельных сессиях) и [deepreview](https://github.com/mechanai/deepreview) (конвергенция классификации новизны, маршрутизация по эффективному размеру, Points of Agreement). Чисто конфигурационное решение, ноль дополнительных зависимостей.

> **Заимствование, а не копирование**: из тяжёлых пайплайнов извлекаются только принципы облегчённого дизайна; избыточные функции покрываются существующими agents/skills, новые не добавляются. Следуем принципу «упрощение важнее дополнения», каждая итерация нацелена на чистое сокращение токенов.
>
> **Источники механизмов этого раунда (v27)**: поток действий OPSX (update/verify/четыре вопроса) интегрирован в spec-workflow; сбор контекста в отдельных сессиях и безопасность кэша промптов (стабильный статический префикс, изменчивый контент в конце payload) заимствованы у pi и oh-my-opencode-slim; гейт итераций impact×confidence÷cost перенесён в deep-worker; Points of Agreement (пометка точек согласия максимальной уверенностью) заимствованы у deepreview; gh-cli дополнен rate limit и gh-aw из cli/cli v2.97.
>
> **Отклонено после оценки**: прогрессивное раскрытие и wait-what из mattpocock/skills (их ценность уже покрыта ленивой загрузкой существующих навыков); superpowers не имеет настроечных ручек — остаётся в виде строки плагина.

### Вехи итераций

27 итераций с версии v1, непрерывное соответствие лучшим практикам upstream-репозиториев:

- **v1-v7 (Основа)**: Привязка двух моделей, система ролей агентов, маршрутизация по намерениям, глобальные правила AGENTS.md, каталог skills, базовые разрешения
- **v8-v15 (Ревью + Спецификации + Контракты)**: code-review двухосевая калибровка, spec-workflow, согласование с gh-cli, контракт отказа, фоновые проверки
- **v16-v22 (Непрерывное упрощение)**: Команды 29→18 (-38%), AGENTS.md 290→211 (-27%), построчная no-op обрезка, валидация схемы с удалением мёртвых ключей
- **v23-v25 (Согласование + Безопасность)**: Интегрировано 6 upstream-репозиториев, gh-cli v2.97 предупреждение об инъекции, уточнение procedure-driven промптов, настройка DCP
- **v26 (Упрощение этого раунда)**: ужесточение prune:true и tool_output 800/20480, DCP переведён на процентные пороги 60%/30%, grilling введён вместо writing-great-skills, opencode-config упрощён 131→64, code-review классификация + validator, gh-cli дополнен gh status, в AGENTS.md добавлен User Override, дисциплина стоимости делегирования у orchestrator, 7 файлов агентов — чистое сокращение на 22 строки
- **v27 (Удаление/миграция/добавление)**: удалены мёртвая конфигурация batch_tool, неэффективные `write: deny` у агентов только-чтение и 3 избыточные bash-строки; секция Context Management перенесена в подраздел orchestrator; белые списки bash для агентов только-чтение, в read добавлены `.env`; добавлен навык tech-debt-audit; описания 15 навыков сокращены на 30-40%; gh-cli дополнен 5 пунктами (rate limit, хостинг gh skill, gh-aw и др.), в code-review добавлены Points of Agreement, spec-workflow дополнен двумя вопросами update, orchestrator получил сбор контекста в отдельных сессиях и безопасность кэша промптов, deep-worker получил impact×confidence÷cost

## Руководство по использованию

### Режим 1: Автоматическая маршрутизация Orchestrator (по умолчанию)

Опишите задачу естественным языком — Orchestrator автоматически проанализирует намерение, выберет наиболее подходящего агента и модель для выполнения.

```text
«Помоги разобраться с ошибкой в этом интерфейсе входа»     → oracle анализирует причину → диагностический отчёт
«Оптимизируй этот цикл, производительность ужасная»        → oracle анализирует → deep-worker выполняет оптимизацию
«Проверь этот PR»                                          → reviewer проводит многомерное ревью → отчёт с уровнями
«Хочу добавить функцию экспорта в модуль пользователей»    → planner составляет план → deep-worker реализует
«Как использовать API use() в React 19»                    → librarian ищет документацию → сигнатуры и примеры
```

### Режим 2: Прямой вызов через псевдонимы команд

| Сценарий | Команда |
| --- | --- |
| Сложная реализация / многофайловые изменения | `/deep` |
| Лёгкие правки / редактирование одного файла | `/quick` |
| Составление технического решения / архитектуры | `/plan` |
| Поиск багов / глубокий анализ | `/oracle` |
| Код-ревью | `/review` |
| Внешний поиск / поиск API | `/search` |
| Фронтенд / UI-задачи | `/ui` |
| Обсуждение решений / сравнение альтернатив | `/consult` |
| Структурированная отладка | `/oracle` |

### Типичные рабочие процессы

**Разработка новой функции (по спецификации):**
```text
/spec-propose  → /spec-apply  → /review
```

**Поиск багов:**
```text
/oracle  → /deep  → /rmslop  → /commit
```

**Код-ревью:**
```text
/review-pr   ← ревью PR + автоматическая публикация комментариев
/review      ← двухосевое параллельное ревью
```

## Философия дизайна

- **Чисто конфигурационное решение, ноль дополнительных зависимостей** — все возможности реализованы через `opencode.jsonc` + `agents/*.md` + `skills/*/SKILL.md` + `AGENTS.md`
- **Максимальное использование двух моделей DeepSeek V4** — Pro для рассуждений и принятия решений, Flash для поиска и лёгкого исполнения
- **Эффективность токенов прежде всего** — ссылки на пути вместо вставки файлов, загрузка навыков по требованию, многоуровневое управление сжатием
- **Плагины усиливают, но не перетягивают одеяло** — superpowers обеспечивает процессную дисциплину, DCP с интеллектуальным сжатием заменяет простое усечение (процентные пороги адаптивны, нативная compaction как подстраховка)
- **Разделение исполнения и исследования** — deep-worker/light-orchestrator: запрет исследований/делегирования; explore/librarian: запрет изменений
- **Непрерывное улучшение** — reflect систематизирует выявление проблем, code-review с двухосевой калибровкой гарантирует качество
